## 1. Situação por Componente

### ForgeOS — 🟢 **FUNCIONAL E VALIDADO EM CAMPO**
A stack de provisionamento foi reimplementada, deployada na BTV E10 e certificada
por suíte de testes (30/30). Detalhes em [`ForgeOS/README.md`](../ForgeOS/README.md).

| Capacidade | Estado | Evidência |
|---|---|---|
| AP `RTL8189FTV_AP` + DHCP + DNS cativo | ✅ | cliente recebe lease, wildcard → portal |
| Portal web offline (PSK + EAP/eduroam) | ✅ | Pico.css v2 local, HTTP 200 |
| Tela HDMI dual-QR (design industrial) | ✅ | screenshot do framebuffer validado |
| Provisionamento real com internet | ✅ | OpenWrt → lease `192.168.1.103` → ping wlan0 |
| Rollback de falha (AP restaurado) | ✅ | ciclo de integração <20s |
| Fallback rede caída >5min → AP | ✅ | watchdog FAIL_LIMIT |
| Sobrevive a reboot | ✅ | boot limpo, 4/4 serviços ativos |

**Bugs críticos corrigidos nesta sprint** (todos cobertos por testes):
1. Socket stale do wpa_supplicant travava reconexões
2. `KillMode` do systemd matava o apply no teardown
3. Watchdog restaurava AP durante tentativa legítima (race)
4. Teste de internet saía pela eth0 (falso positivo)
5. Ausência de cliente DHCP na imagem
6. Rollback não reativava portal/display (não-determinístico)
7. Console (fbcon/getty) sobrescrevia o framebuffer (flicker/quebra visual)
